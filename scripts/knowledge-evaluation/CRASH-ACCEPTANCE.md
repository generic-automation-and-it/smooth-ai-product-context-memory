# Isolated process-kill acceptance

`crash_acceptance.py` runs actual SIGKILL and restart tests against the fixed `mimi-ks-test-service` container through the existing `unraid` SSH alias. It also snapshots and restores the isolated `mimi-ks-test-core` database `knowledge_eval_linux`. Obtain exclusive use of these test fixtures before running: restore removes **all changes in this test database since the snapshot**, including other evaluations. This is not a production command or deployment script.

The core and service must already be running with SSH forwards at `127.0.0.1:15141` and `127.0.0.1:15142`. The journal must be mounted at `/app/data/captures.db`, with Python and SQLite available inside the service container. The harness checks container names and database identity before writes, seeds its own synthetic scope, and uses three bounded capture jobs (hard maximum eight). It consumes real provider calls configured in the test service.

Pass an external protected KEY=value file containing `CONTEXT_MEMORY_READ_TOKEN`, `CONTEXT_MEMORY_WRITE_TOKEN`, `MIMI_KNOWLEDGE_READ_TOKEN`, and `MIMI_KNOWLEDGE_WRITE_TOKEN`. The harness ignores inherited credentials and endpoints. Tokens are never command arguments or report fields. Restrict Windows ACLs; Unix mode 600 is required.

```text
python scripts/knowledge-evaluation/crash_acceptance.py --credentials-file EXTERNAL_TEST_CREDENTIALS.env --output EXTERNAL_CRASH_REPORT.json --disruptive-test-containers
```

The report records actual observations for acknowledgement persistence; direct core write, query and body retrieval while the optional service is stopped; reservation IDs, charged call/token/cost budgets and absolute deadlines surviving process loss; same-payload replay and changed-payload conflict; and a real older-corpus restore causing an epoch mismatch and reconciliation pause. A reserved provider call lost during SIGKILL remains charged: if it leaves too little allowance for a fresh reservation, `partial` / `budget_exhausted` is a successful budget-protection observation, not permission to clear the reservation.

Restore stops the isolated core and uses a one-shot container with its exact existing image ID, fixed test environment file and fixed context mount, then restarts core readiness before the service. It never invokes restore inside a serving core. After public recovery disclosure, reconciliation pins both epochs and explicitly acknowledges the restore. Checks cover refusal without acknowledgement or with a wrong epoch; archived prior receipts/usage; unchanged spend and deadline without extra allowance; one new generation across retries; changed-payload conflict; and re-comparison under new operation keys without duplicate versions. If the preserved deadline has expired, one explicit time-only continuation is permitted and reported; spent calls and abandoned reservations remain charged.

For the ambiguous commit case, the harness briefly takes a SQLite writer lock without changing rows. Once the durable pending payload exists, this prevents the service from saving its next journal update. It verifies the core operation receipt exists while the journal still contains the pending operation, kills the service, then verifies recovery retains exactly the same versions and sources. Missing the timing window is an honest failed observation; it is never reported as a passed crash test. The lock is bounded and the harness restarts the service on failure where possible.

Archives remain under `/app/.context/crash-tests/<runId>` in the isolated core container; reports belong outside Git. No production container, live corpus, provider configuration, or other resource is cleaned up. Pure guard tests are separate from real acceptance: `python -m unittest discover -s scripts/knowledge-evaluation -p "test_crash_acceptance.py"`.

Bounded resume options reuse existing captures after an observed harness expectation failure, without repeating setup or spending another capture job. `--resume-reservation-pause EXTERNAL_REPORT.json` accepts the earlier strict-terminal budget-pause checkpoint; `--resume-restored-capture EXTERNAL_REPORT.json` accepts the failed restore-pause checkpoint with its externally recorded `existingCaptureId`. Resume refuses unrelated reports or scopes. Preserve the failed diagnostic in the final report: a later passing recovery does not erase the original observation.

October 3 isolated acceptance completed all seven checks in `crash-reconciliation-linux.json` outside Git, with three acknowledged jobs in the extended run and eight across the earlier and extended crash runs. One abandoned 8,000-output-token reservation remained charged and caused a deliberate budget pause. The real commit-before-journal kill recovered without additional versions or sources. One-shot restore disclosed missing receipts; the fixed clarification boundary rejected normal continuation with 409. Explicit reconciliation retained the previous two settled calls and the original expired deadline, then one operator-authorized 60-second time-only allowance allowed generation 1 to finish. Repeated reconciliation preserved its UUID/version/source fingerprint and generation.

Re-comparison may produce multiple independently meaningful claims. The recovery assertion requires the restored scope's exact UUID set to match the new committed receipt, every new record to be version 1 and the receipt to report zero version bumps; it then checks identical replay. This run produced two distinct records, so an earlier single-record harness expectation was corrected. The report retains that expectation failure and the observed earlier clarification-202 regression; service boundary regressions were fixed and independently tested before resuming the same captures.
